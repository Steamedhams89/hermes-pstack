### Autopilot-stack

**You own the local review sequence, never the landing.** Build and verify the queue within the active session, then hand the operator ordered local artifacts for review. This port does not implement a Graphite stack controller or autonomous landing.

1. **Run bounded owner work.** Use `delegate_task` only for independent scoped changes. Each owner builds, verifies, triages evidence, and returns a local decision trail; it does not create or publish a pull request without separate authority.
2. **Audit only while this active session is running.** A timed wake chain or recurring status loop requires separately authorized Hermes automation. Otherwise preserve the current state and next action for manual re-entry.
3. **Hold the operator gates.** State the plan, wait for an explicit go, and honor an explicit stop with zero further writes. Track the objective in `todo` only for this session.
4. **Verify at STACK-READY.** The owner reports STACK-READY with the exact head SHA. The root swarm-verifies that SHA, fan-out per the **swarm** skill: parallel independent verifiers re-running the gates at that SHA, a live runtime floor over the load-bearing behavior, and a receipts-and-diff audit that distrusts the PR body. The swarm aggregates to one verdict. Findings go back to the owner, and nothing enters the stack unverified.
5. **Prepare the ordered review sequence on a clean verdict, never ship.** A clean verdict records evidence; it does not create, update, or merge a pull request.
6. **Use one coordinator for ordering and parallel writers only for independent builds.** Graphite commands and force-push topology changes are unavailable in this port unless a separate, explicitly authorized Git workflow supplies them.
7. **Re-verify any change whose base or diff moved.** Preserve Git terms as review evidence, but do not invoke a Graphite restack or automatic push from this content-only playbook.
8. **Deliver the ordered review evidence.** The operator decides whether to create, update, merge, or publish a pull-request chain through separately authorized ordinary Git/GitHub tooling.

**Choosing between the autopilots.** Autopilot-full when the PRs are independent and landing authority is granted. Autopilot-stack when the operator wants review before landing, the work is sequenced or coupled, or merge authority is withheld.

**Reply:** links to the stack root and tip, a one-line verdict summary per link, and anything parked or excluded with the reason.
